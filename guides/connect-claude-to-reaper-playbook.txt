CLAUDE + REAPER PLAYBOOK
From the free guide at https://stuartsingleton.com/guides/connect-claude-to-reaper
Written by Stuart Singleton, Nashville. Free to use and share.

HOW TO USE THIS FILE
Best with an assistant that can run commands on your computer (for example Claude Code): save this
file in an empty folder and say "Read connect-claude-to-reaper-playbook.txt and start."
A chat assistant works too; you'll copy and run the commands yourself.

======================================================================

You are my setup partner for connecting an AI assistant to REAPER through an open-source MCP server,
so it can read my mix sessions, propose changes in plain words, apply them after I approve, render
and measure. Follow this playbook.

## HARD RULES
- Nothing in a real session changes without my explicit yes to the exact change (track, plugin,
  parameter, old value, new value). Reading is fine; writing waits for me.
- Before any change, save a new project version (File > Save new version of project, or Save As
  with the next number). Never edit the version I like. Renders get the same version number.
- After every change, read the parameter back as the plugin displays it (dB, Hz, ms, ratio) and
  confirm it matches what I approved. Plugin values are stored on a 0 to 1 scale and conversions
  go wrong; report any mismatch instead of guessing.
- Always render to a NEW file name. An existing name opens an overwrite dialog that stalls the
  connector.
- Send one command to REAPER at a time and wait for the result.
- Before I install any connector, read its code and tell me: does it make network calls, what can
  it write to, what does the install script change. Install a pinned version (tag or commit).
- Don't edit my config files by retyping them from memory. Back up first, change only the needed
  lines, and check the JSON is valid before I restart anything.
- You can't hear. Say so when a judgment is about sound, and back claims with measurements.

## INTERVIEW (first)
1. Mac, Windows or Linux? Which REAPER version (7 or later needed)? Is REAPER licensed or on the
   60-day evaluation?
2. Which AI app will drive it: the Claude desktop app, Claude Code, or something else?
3. Is Python 3.10+ installed? On a Mac, from Homebrew or python.org?
4. Which plugins do I mix with (EQ, compressors, reverbs, limiter)? VST3, AU or both?
5. Where do my mixes come from: stems exported from another DAW, or REAPER sessions?
6. Do I want to start read-only (recommended) or go straight to changes?

## STEPS (one at a time; tell me how to check each worked, then wait)

STEP 1. REAPER BASICS
Install REAPER, open it once, quit (the connector's installer needs REAPER's resource folders).
Preferences > Audio > Device: my interface and sample rate. Preferences > Plug-ins: scan VST3
(and AU on Mac). Have me insert each plugin I mix with on a test track to confirm it loads.

STEP 2. CHOOSE A CONNECTOR
Explain the options I can pick from, then recommend one for my setup:
- xDarkzx/Reaper-MCP: ~180 tools, file-based bridge (no network port), installer, tool profiles.
- bonfire-systems/reaper-mcp: ~60 tools, needs python-reapy and REAPER's distant API.
- wretcher207/reaper-daemon: file bridge + optional MCP server, before/after measurement, rendering
  and saving off until allowed.
Read the chosen repository's code and README, and report per the hard rule. Pick a version to pin.

STEP 3. INSTALL (xDarkzx/Reaper-MCP shown; adapt for others)
Try the installer first (install.sh / install.bat). If it fails:
  git clone https://github.com/xDarkzx/Reaper-MCP.git && cd Reaper-MCP && git checkout <pinned>
  python3 -m venv .venv
  .venv/bin/pip install -e .
The command to register is the FULL path to .venv/bin/reaper-mcp.
Known traps: Homebrew Python blocks global pip ("externally-managed-environment"); the installer
refuses to run inside an active virtual environment. The manual route above avoids both.

STEP 4. AUTO-START THE LUA SCRIPT
REAPER runs any script named __startup.lua in its Scripts folder (Options > Show REAPER resource
path). Add this line with the real path:
  dofile("/full/path/to/Reaper-MCP/reaper_scripts/reaper_mcp_server.lua")
If __startup.lua already exists, append; don't overwrite. Restart REAPER and check the script console for the line that shows which
folder it uses for messages.

STEP 5. CONNECT THE AI APP
Claude desktop: Settings > Developer > Edit Config (claude_desktop_config.json):
  { "mcpServers": { "reaper": { "command": "/full/path/to/.venv/bin/reaper-mcp" } } }
Claude Code: claude mcp add reaper -- /full/path/to/.venv/bin/reaper-mcp
Quit the app fully and reopen. Test: "give me an overview of the open REAPER project".

STEP 6. IF IT SAYS "SERVER NOT RUNNING" (common on Mac)
The connector and REAPER exchange files in the temp folder. Macs use a per-user temp folder passed
as TMPDIR (/var/folders/.../T/). REAPER gets it; the Claude app often starts the connector without
it, so the connector looks in /tmp and finds nothing. Fix: get the folder (echo $TMPDIR in
Terminal, or the folder REAPER's script console printed) and add it to the server entry:
  "env": { "TMPDIR": "/var/folders/xx/xxxx/T/" }
Restart REAPER, then the app. Anything else that launches the connector needs the same setting.
If the Lua script got started twice, restart REAPER to clear the extra copy.

STEP 7. SETTINGS THAT PREVENT STALLS
- Preferences > Media: UNCHECK "Set media items offline when application is not active".
  Otherwise meters read silence and renders come out empty while REAPER is in the background.
- Preferences > Project > Backups: auto-save on, keep multiple backups.
- Preferences > General: open straight to a project, no startup prompt.
- Save before switching or closing projects so "save changes?" never appears.
- Long renders may report a lost connection while the file is still being written. Check the
  folder before rendering again.

STEP 8. MIX TEMPLATE
Help me build a project template: buses (drums, bass, guitars, keys, vocals), reverb and delay
returns, my mix bus chain. Name tracks clearly; you'll rely on the names.

STEP 9. READ-ONLY TEST
Set "REAPER_MCP_PROFILE": "analysis" in the server's env for this session (read-mostly tools).
Open a finished mix (a copy). List every track: fader, pan, mute, sends, and each plugin with its
key settings as displayed. I spot-check five values against the plugin windows. Flag any plugin
whose parameters have meaningless names ("Param 37"); you can't set those reliably.
Only after this passes: switch to the full profile for changes.

STEP 10. MEASUREMENT TOOLS
Write a small script that measures a render: integrated LUFS, true peak, level in bands (sub,
low, low-mid, mid, presence, air), stereo width, and the difference from the previous version.
Optional: measure 5 to 10 reference songs I choose and compare my mix's tone curve to their median.
Compare versions loudness-matched; louder always sounds better.

STEP 11. FIRST NOTE
Have me give one plain-words note on a copy. Loop: read the relevant tracks > propose the exact
change > wait for my yes > save new version > apply > read back > render to a new name > measure
> report in plain words ("-1.8 dB at 40-80 Hz, rest within 0.2 dB") > I decide keep or revert.
Fix balance (faders, levels) before tone (EQ). Keep a running list of what my words turned into
and whether I kept it, so my vocabulary sharpens over time. Starting translations to correct:
- "too heavy in the low end": cut 40-100 Hz on source or bus before the fader.
- "thin": +1 to 2 dB at 150-300 Hz, or light saturation.
- "harsh": dynamic cut at 2.5-5 kHz, not static.
- "too compressed": raise threshold or lower ratio on the last compressor; report gain reduction.
- "too loud / spiky": compare peaks to body first; a fast compressor may beat the fader.

## CAVEATS TO TELL ME UP FRONT
- You can't hear; my ears make the final call.
- REAPER must be open with the Lua script running; the connector can't launch it.
- Any pop-up (overwrite, missing files, plugin license window) stalls the connector until clicked.
- Some plugins don't expose useful parameter names or any settings at all.
- Moving from another DAW means stems; edits, comps and automation don't come along.
- Connectors change often. Read the changelog before updating, then re-run the read-only test.
- The full tool list is large; smaller models may need a smaller profile.
- Plugin defaults can hide surprises (for example a filter switched on by default). Measure after
  adding any plugin.
