An always-on machine you can reach from anywhere

I turned a 2014 Mac mini that couldn't run a current macOS into an always-on Linux server. It runs my automation, an offline library with a small local AI, and it's reachable from my phone anywhere in the world. I never opened a port on my router. The trick is Tailscale, a private network that connects your devices directly. This guide is the whole setup, including every place I got stuck. 00OverviewRead first

What you're building

A computer that never sleeps, sits at home on a wired connection, and does the jobs your laptop shouldn't. You reach it from your phone, laptop or anywhere else through Tailscale, without exposing anything to the open internet.

  • File sharing you can reach from anywhere.
  • Automation like n8n workflows that run while your laptop is closed.
  • An offline library: Wikipedia, medical references and repair guides served on your home network, plus a small local AI that answers from them.
  • Anything else always-on: home automation, a camera recorder, a print farm controller.

What it costs

An old computer you already own, a little electricity, and nothing for Tailscale for personal use. Its free Personal plan covers up to 6 users with unlimited personal devices, for non-commercial use. A battery backup and a better drive are the only purchases worth making early.

How long it takes

An afternoon for the base server. Each service after that is an evening.

01Hardware~30 min

Pick the machine

Almost anything works: an old Mac mini, a laptop with a dead screen, a cheap mini PC. What matters is that it's quiet, sips power, and has a wired Ethernet port.

  • Check the exact model before buying parts. On older Mac minis the drive and sometimes the RAM can be upgraded. On newer ones both are soldered, so external storage is the only option. The model decides whether a drive purchase is even possible.
  • Swap a spinning hard drive for an SSD if you can. It's the single biggest speed and reliability upgrade for an old machine.
  • Plug it into the router with Ethernet. Wi-Fi is the most common reason a home server "randomly" drops off.
  • Keep its job list short. An old machine with fixed RAM can do a few things well, not everything.
What broke for me

My plan was to keep the Mac mini on macOS. Three weeks in, I realized it couldn't run Tailscale at all: the app needs a newer macOS than a 2014 mini can install. Check that your OS can run the current Tailscale client before you plan anything else. If it can't, install Linux. That's what saved the machine.

02OS~1 hour

Install Linux

Ubuntu's current long-term support (LTS) release is the easy default. It gets security updates for years and every tutorial covers it.

  1. Back up anything on the machine first. The install erases it.
  2. Download the Ubuntu ISO and write it to a USB stick with balenaEtcher.
  3. On a Mac: power off, plug the stick into a port on the back, press power and immediately hold Option. Pick EFI Boot. On a PC, use the boot menu key (often F12).
  4. Install, set a strong password, and pick a hostname you'll remember, like server.
What broke for me

After picking EFI Boot, the screen stayed black for a minute or two. That's normal on old Macs. I almost restarted in the middle of it. And if no EFI Boot option shows up at all, the stick didn't write as bootable: rewrite it rather than troubleshooting the computer.

Also caught me

The installer gave my login account a different name than the computer's hostname. SSH needs the account name, not the computer name, so ssh server@server failed and looked exactly like a network problem. Write down both the username and the hostname the moment the install finishes.

On disk encryption: full disk encryption makes the machine stop at a passphrase prompt after every power cut, with nobody home to type it. If the server stores nothing sensitive itself (your files live on a NAS or are backed up elsewhere), skipping it can be the right trade. Decide on purpose.

03Always on~10 min

Keep it awake

Desktop Linux goes to sleep like a laptop. A server that sleeps is a server you can't reach. Turn sleep off at the system level, not just in settings:

sudo systemctl mask sleep.target suspend.target \
  hibernate.target hybrid-sleep.target

Then in Settings → Power, set Screen Blank to Never and Automatic Suspend to Off. If the machine has a lid, set it to do nothing when closed.

04Network~20 min

Tailscale everywhere

Tailscale gives each of your devices a private address on your own network (a "tailnet"). They find each other wherever they are, at home, on cell data, in a hotel. Nothing is exposed to the internet.

  1. Make a Tailscale account. Pick the login you want to own this long-term (more on why in step 8).
  2. On the server: 
    sudo apt install -y curl
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up
    Open the link it prints and approve the machine.
  3. Install the Tailscale app on your phone and laptop and sign in with the same account.
  4. In the admin console, find the server and disable key expiry for it. New tailnets expire each device's login after 180 days by default. That's good for laptops and bad for a server nobody is sitting at. Tagged devices (step 8) have expiry turned off automatically.
What broke for me

Minimal Ubuntu doesn't include curl. The install line failed with "curl not found" and then "tailscale: command not found", which reads like two problems but is one. Install curl from apt first. Not from snap, which sandboxes it.

On a Mac

Typing tailscale status in the Mac Terminal says "command not found" even when Tailscale is working fine, because the Mac app keeps its command-line tool inside the app. It looks broken and isn't. Use the menu bar app, or add an alias to the full path.

05Access~30 min

Names and SSH

Turn on MagicDNS in the Tailscale admin console (DNS tab). Then you reach machines by name, like server, instead of memorizing addresses.

  • Name it in two places. The name in the Tailscale console and the computer's own hostname are separate settings. Set them to match, or names will disagree in confusing ways later.
  • Keep the Tailscale address as a fallback. If ssh you@server fails but ssh you@100.x.y.z works, it's a naming problem, not a network problem. That one test saves an hour.
  • Machines shared with other people only resolve by their full name (server.your-tailnet.ts.net), not the short one.

SSH, so you never sit at it again

sudo apt install -y openssh-server
sudo systemctl enable --now ssh
sudo ufw allow ssh
sudo ufw enable

From your laptop: ssh yourusername@server. For a desktop view instead, Ubuntu has Remote Desktop under Settings → System.

What broke for me

I pasted a whole block of commands into an SSH login at once. The extra lines got eaten as password attempts, the server hung up, and the rest of the commands ran on my own Mac instead. Paste one line at a time and wait for the server's prompt.

06Jobsan evening each

Run services

Use Docker, with one docker-compose.yml per service in a single folder (I use /opt/stack/) that's tracked in git. Then the whole server is a set of files, and rebuilding it from scratch is: install Docker, clone the folder, start everything. An afternoon instead of a weekend of remembering what you installed.

curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER   # then log out and back in

Install Docker from the official script or apt, not snap. Snap's sandbox fights the folder mounts Docker depends on.

Good first services

  • n8n for automations that run on a schedule.
  • Kiwix to serve offline copies of Wikipedia, medical wikis and repair guides to any browser on your network.
  • Ollama for a small local AI. On my 2014 mini with no graphics card, a 3 billion parameter model produces about 7 tokens (roughly five words) a second. Slow, but fast enough to read along.
  • Watchtower or diun to update containers automatically or tell you when updates exist.
Worth knowing

Home Assistant in Docker is the "Container" version, which has no add-on store. Every tutorial that says "just install the add-on" stops applying, and you wire each piece up yourself. Docker makes it easier to start, not easier to run.

07Storage~1 hour

Add a NAS

If you have a Synology, put it on the same tailnet and your files follow you everywhere.

  • Install the official Tailscale package from Synology's Package Center. Use it instead of a subnet router.
  • Turn off QuickConnect. It's a door into your NAS from the internet. With Tailscale you don't need it, and leaving both on makes the secure path optional.
  • Make a personal admin account, stop using the built-in admin, and turn on two-factor login.
  • Turn on the firewall: allow your home network and Tailscale, deny the rest.
  • Never run a big operating system upgrade on the NAS over Tailscale. You'll lose the connection halfway through.
What I learned

A Synology can't act as a plug-in drive for one computer. Its USB ports are for drives going into it. For near-local speed, run a second Ethernet cable straight from your computer to the NAS on its own little network. And edit on a fast local SSD, archive to the NAS. Editing 4K video straight off a network share feels broken, and it isn't the NAS's fault.

08Security~1 hour

Who can reach what

  • Never forward ports on your router. Tailscale is the way in. My router once logged a burst of port scans aimed at my file server. It blocked them and nothing got in, but there's no reason to offer the door.
  • If something truly has to be public (an incoming webhook, say), use a tunnel: Cloudflare Tunnel for permanent, Tailscale Funnel for quick tests. Never a router forward.
  • One tailnet, with tags and access rules, not separate accounts per project. The access rules (ACLs) say which tagged machines can reach which.
  • Make test machines a dead end. Tag them so you can reach them, but they can reach nothing. Anything running untested code shouldn't be able to see your NAS.
  • Sharing a machine is not giving a login. When you share your NAS with a collaborator through Tailscale, they still need an account on the NAS itself. Two layers, on purpose.
  • Decide early which login owns the tailnet. Moving a tailnet from a personal account to a business account later is not clean.
09Unattended~20 min

Power and updates

  • Battery backup (UPS) for the server, the router and the NAS. Short outages stop mattering, and drives don't get cut off mid-write.
  • Power back on automatically after an outage, if your machine's firmware has the setting.
  • Automatic security updates: 
    sudo apt install -y unattended-upgrades
cat /etc/apt/apt.conf.d/20auto-upgrades
    Both lines should end in "1".
What broke for me

On a fresh Ubuntu install, automatic updates were already installed, so the setup dialog never appeared and I almost assumed it was on. Check that file instead of assuming. A server runs untouched for months, so this one matters.

10Safety~1 hour

Backups

  • RAID is not backup. Two mirrored drives protect you from one drive dying, not from fire, theft, ransomware or you deleting the wrong folder.
  • Keep an offsite copy. I use Synology Hyper Backup to Backblaze B2.
  • Back up before you load data in. An unbacked NAS that becomes the only copy of everything is the worst position to be in.
  • Your server's setup lives in git (step 6), so the machine is replaceable. Its data is what needs backing up.
  • Do one restore test. Pull a single file back from the backup to a different place and open it. An untested backup is a belief, not a backup.
11Outages~15 min

When the internet is down

Tailscale needs the internet to set up new connections. If your internet goes out, your devices at home can still reach the server, but only by its local address.

  • Give the server a fixed local address with a DHCP reservation in your router.
  • Write that address on paper and keep it with your router. Save it as a bookmark on your phone too.
  • A battery-powered tablet with Kiwix and copies of the library files works even with no router and no server. That's my last fallback.
