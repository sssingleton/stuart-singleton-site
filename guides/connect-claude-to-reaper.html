REAPER

Mix by talking, with your own plugins

I connected Claude to REAPER so I can give a mix note in plain words ("the electric guitar is too loud", "the low end is too heavy") and have it read the session, propose the exact change, and apply it once I say yes. It runs on my own computer, with my own plugins. Every change saves as a new version, so nothing it does is permanent. This guide is how it's wired, plus the setup problems that cost me the most time: the connector that can't find REAPER, renders that come out silent, and a dialog that freezes everything.

What this does

The loop:

you: "guitar is too loud in the chorus"
→ Claude reads tracks, sends, plugins
→ proposes the exact change:
  "EG bus: Pro-C 2, 4:1, 2 ms attack,
   -24 dB threshold; fader -4 dB. OK?"
→ you say yes, tweak, or no
→ it saves a new version, then applies
→ renders and measures the bounce
→ you listen: keep, revert, or a new note

Claude talks to REAPER through a small open-source program called an MCP server (MCP is the standard way AI apps connect to other software). It runs on your computer next to REAPER. Your audio never leaves the machine; only the text of the session (track names, plugin settings, measurements) goes to Claude.

What you need: REAPER 7 or later, a computer that already runs your plugins, Python 3.10 or later, and the Claude desktop app (or Claude Code). About an hour for setup, most of it in steps 04 to 06.

01Choose5 min

Why REAPER and not Logic

Logic has community MCP servers too, but they reach Logic through its interface (accessibility scripting and control-surface messages). That covers faders, pans and transport, and gets unreliable deep inside third-party plugins. REAPER's scripting API can read and set every exposed parameter on any VST3 or AU plugin, add and remove plugins, change routing and render, without touching the screen. That's the whole reason to switch.

  • What you keep: your third-party plugins. REAPER hosts VST3 and AU.
  • What you lose: Logic's stock plugins and instruments, and Logic projects don't open in REAPER. You bring stems over.
  • Cost: REAPER has a free, fully working 60-day evaluation. After that a license is $60 (personal use, or a business under $20,000 a year) or $225 (commercial), from reaper.fm.

I still write and track in Logic. Mixes move to REAPER as stems: one WAV per track, all starting at bar 1 so they line up.

02Choose15 min

Pick a connector

Three open-source options I looked at, all on GitHub. All three only talk to your local copy of REAPER:

  • xDarkzx/Reaper-MCP: the one I use. About 180 tools covering tracks, FX parameters, sends, rendering and audio analysis. It talks to REAPER through files on disk, not a network port, and has an installer. Apache 2.0 license.
  • bonfire-systems/reaper-mcp: about 60 tools. Talks through python-reapy, which means turning on REAPER's "distant API" and running Python inside REAPER.
  • wretcher207/reaper-daemon: a file bridge plus an optional MCP server, with before-and-after measurement built in. Rendering and saving are off until you allow them, which is a nice safe default.

Read the code before you install. This program will be able to change your sessions. Ask Claude to read the repository first and tell you whether it makes any network calls, what it can write to, and what the install script changes. Then install one specific version (a tagged release or commit) rather than whatever is newest.

03Setup20 min

Set up REAPER

  • Install REAPER, open it once and quit. The connector's installer looks for the folders REAPER creates on first launch.
  • Preferences → Audio → Device: pick your audio interface and confirm the sample rate.
  • Preferences → Plug-ins: scan VST3 (and AU on a Mac). Insert each plugin you mix with on a test track to confirm it loads and its window opens.
  • Make a mix template: your usual buses (drums, guitars, vocals, reverb and delay returns) and your mix bus chain, saved as a project template. Every new mix starts from it.
Check this early

Some plugins name their settings clearly (Pro-Q 4 says "Band 1 Frequency"); others list "Param 37". Before you rely on Claude to set a plugin, ask it to list that plugin's parameters. If the names mean nothing, it can't set them reliably.

04Setup20 min

Install the connector

For xDarkzx/Reaper-MCP. Its installer (install.sh on Mac and Linux, install.bat on Windows) does all of this when it works. When it doesn't, the manual version is short:

# 1. get the code, pinned to a version you've checked
git clone https://github.com/xDarkzx/Reaper-MCP.git
cd Reaper-MCP
git checkout <tag-or-commit>

# 2. give it its own Python environment
python3 -m venv .venv
.venv/bin/pip install -e .

# 3. the command Claude will run:
#    /full/path/to/Reaper-MCP/.venv/bin/reaper-mcp

The other half is a Lua script that runs inside REAPER and answers the connector. REAPER automatically runs any script named __startup.lua in its Scripts folder (Options → Show REAPER resource path). Put this line in it (with your real path) so the connector's script starts every time REAPER opens:

dofile("/full/path/to/Reaper-MCP/reaper_scripts/reaper_mcp_server.lua")

If __startup.lua already exists, add the line at the end; don't replace the file. To run the script once by hand instead: Actions → Show action list → Load ReaScript → Run.

What broke for me

On a Mac with Homebrew Python, a plain pip install is blocked ("externally-managed-environment"), and the installer refuses to run inside a virtual environment. I did steps 2 and 3 by hand and pointed Claude at the full path of the command inside .venv. Using the full path also stops it from breaking when the app's PATH differs from your terminal's.

05Setup5 min

Connect Claude

Claude desktop app: Settings → Developer → Edit Config opens claude_desktop_config.json. Add the server:

{
  "mcpServers": {
    "reaper": {
      "command": "/full/path/to/Reaper-MCP/.venv/bin/reaper-mcp"
    }
  }
}

Quit Claude completely and reopen it. With REAPER open, the REAPER tools show up in the chat's tools menu.

Claude Code: claude mcp add reaper -- /full/path/to/Reaper-MCP/.venv/bin/reaper-mcp

First check: ask Claude to "give me an overview of the open REAPER project". An empty project is fine. If you get track count and tempo back, you're connected. If you get "server not running", go to step 06.

06Fix10 min

Fix "server not running"

This one cost me the most time, and it's a Mac thing. The connector and the Lua script inside REAPER pass messages through a folder in your temp directory. On a Mac each user has a private temp folder (it looks like /var/folders/xx/xxxx/T/), and its location is passed to apps in a setting called TMPDIR. REAPER gets it. The Claude app can launch the connector without it, so the connector looks in plain /tmp, finds nothing, and reports that REAPER isn't running when it is.

The fix is to give the connector the same folder REAPER uses:

  1. In Terminal, run echo $TMPDIR and copy the result. Or open REAPER's script console: the Lua script prints the folder it uses when it starts.
  2. Add it to the server's entry in the config:
"reaper": {
  "command": "/full/path/to/Reaper-MCP/.venv/bin/reaper-mcp",
  "env": { "TMPDIR": "/var/folders/xx/xxxx/T/" }
}

Restart REAPER, then quit and reopen Claude. Anything else that launches the connector (a script, a scheduled job, another AI app) needs the same setting.

What broke for me

Back up the config file before you edit it, and edit it in a plain text editor. One stray comma and the app ignores every server in the file. If the script ends up running twice (once from startup and once by hand), restart REAPER to clear the extra copy.

07Setup10 min

REAPER settings that stop stalls

  • Preferences → Media: uncheck "Set media items offline when application is not active". It's on by default. While you're chatting with Claude, REAPER isn't the front app, so your audio goes offline: meters read silence and renders come out empty.
  • Always render to a new file name. If the file already exists, REAPER opens an overwrite warning, and the connector waits forever for someone to click it. Version numbers in every render name fix this.
  • Never leave REAPER asking a question. Have Claude save before it switches or closes a project, so "save changes?" never appears, and set Preferences → General so REAPER opens straight to a project instead of a startup prompt. Any window that pops up stalls the connector until someone clicks it in REAPER.
  • One request at a time. REAPER handles commands in order. Firing several at once leads to timeouts.
What broke for me

My first renders were silent until I found the offline setting. Long renders can also report a lost connection even though the file is still written. Check the folder before you re-render, or you'll make duplicates.

08Safety5 min

Every change is a new version

This rule is what makes it safe to let an AI touch a mix.

  • Before each round of changes, save a new version: File → "Save new version of project", or Save As with the next number (Song_v007.rpp → Song_v008.rpp). Tell Claude to always do this first.
  • Never edit the version you like. Changes go into the next number.
  • Preferences → Project → Backups: turn on auto-save and keep multiple backups as a second net.
  • Renders get the same number as the project that made them (Song - Mix v008.wav), so you always know which session made which file.

REAPER's undo history also works on anything the connector changes, but versions survive a crash and a closed project. Undo doesn't.

09Test30 min

First test: read only

Before Claude changes anything, prove it can read a real mix correctly.

  • The connector can load a smaller, read-mostly set of tools. Add "REAPER_MCP_PROFILE": "analysis" to the env in your config for the first session. Switch back to the full set when you're ready for changes.
  • Open a finished mix. Ask Claude to list every track, its fader, pan, sends and every plugin with its key settings.
  • Spot-check five settings against the plugin windows. Ask for values as the plugin displays them (dB, Hz, ms), not the raw 0 to 1 numbers the API uses.
What broke for me

Plugins store settings on a 0 to 1 scale, and the conversion isn't always obvious. A sidechain compressor setup came back listening to its own input, with a 43:1 ratio and a 3-second release, because the values were on the wrong scale. Now the rule is: after any change, read the setting back as the plugin displays it, and confirm it says what was asked.

10MixOngoing

Mixing with notes

  • Approve before apply. Claude proposes the exact change (which plugin, which setting, how much) and nothing moves until you say yes. The desktop app asks before each tool call. You can allow read-only tools permanently and keep it asking for anything that changes the project.
  • Build a mix vocabulary. Your words don't mean the textbook thing. Keep a running list in your project notes of what each note turned into and whether you kept it, so "thicker" ends up meaning what you mean.
  • Fix balance before tone. Ask for fader and level changes before EQ.

Starting translations (correct them to your taste)

  • "Too heavy in the low end" → cut 40 to 100 Hz on the source or bus before touching the fader.
  • "Thin" → +1 to 2 dB at 150 to 300 Hz, or light saturation.
  • "Harsh" → a dynamic cut at 2.5 to 5 kHz, not a static one.
  • "Too compressed" → raise the threshold or lower the ratio on the last compressor, and report gain reduction before and after.
  • "Too loud" on a spiky part → compare its peaks to its body first. A fast compressor may fix it better than the fader.
What I learned

On my first beat, Claude's measurements said the mix was far too dark, and its instinct was more high end. The real problem was balance: bass, piano and kick were drowning a guitar that carried all the top. So levels come first, EQ after.

11Measure30 min

Measure what it can't hear

Claude doesn't listen to your mix. It can measure a render very precisely, which turns "kick feels heavy" into a number you can check.

  • Loudness and peaks: integrated LUFS and true peak for every render, before and after a change.
  • Tone: level in frequency bands (sub, low-mid, presence, air) compared with the last version. "−1.8 dB at 40 to 80 Hz, everything else within 0.2 dB" tells you a change did only what it was meant to.
  • Reference tracks: measure a handful of commercial songs in your genre and compare your mix's tone curve, loudness and stereo width to theirs. Have Claude write a small script for it once and reuse it.
  • Fair A/B: match loudness before comparing versions. The louder one always sounds better.
What broke for me

A tape plugin on my master bus had a low-pass filter on by default that took about 16 dB off the top end. I didn't notice by eye; the measurement against references caught it. Measure after every new plugin, not just at the end.

12Read thisImportant

Caveats

  • It can't hear. Measurements catch a lot but not everything. Your ears make the final call on every version.
  • REAPER must be open with the Lua script running. The connector can't launch REAPER for you.
  • Any pop-up stalls it: overwrite warnings, missing-file prompts, plugin license windows. Someone has to click it in REAPER.
  • Plugins vary. Some expose clear parameter names, some don't, and a few won't expose settings at all.
  • Stems, not sessions. Moving from Logic or Pro Tools means exporting stems. Edits, comps and automation from the old session don't come with them.
  • Connectors are young. They change often, and fixes for wrong parameter scales show up in their changelogs. Pin a version, read the changelog before updating, and re-run the read-only test after.
  • Big tool lists cost context. The full set is about 180 tools. Smaller models may cut the list short; use a smaller profile.
13Rules—

Keep a human in the loop

  • Nothing changes without your yes. Read-only tools can be pre-approved; changes can't.
  • New version before every change. Never edit the version you like.
  • Read back every change in the plugin's own units.
  • Work on copies. Never point it at a client session or a release master you haven't backed up.
  • Release decisions (the final master, the file that goes to your distributor) stay yours, by hand.
